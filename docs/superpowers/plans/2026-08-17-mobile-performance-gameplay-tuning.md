# 移动端性能与玩法手感优化实施计划

## 目标

在不改变单人核心规则和现有星空视觉的前提下，完成 iPhone 横屏适配、移动端渲染降负、轮盘稳定控制、较弱 AI 和可靠渐进合球。

## 实施顺序

1. **输入与时间基准**
   - 在 `src/input.js` 增加设备像素比选择和基于 `dt` 的指数平滑纯函数。
   - `src/main.js` 移除轮盘 250ms 无移动超时，只在指针结束、页面失焦/隐藏或捕获异常时复位。
   - 将轮盘平滑和相机跟随改为按真实时间计算。

2. **视口与渲染**
   - 读取 `visualViewport`，监听尺寸、滚动和旋转变化，并合并同一帧内的重复更新。
   - 将可视尺寸、安全区和浏览器工具栏占用写入 CSS 自定义属性。
   - 粗指针横屏 DPR 上限为 2.25，缓存背景，绘制前按镜头边界剔除不可见对象。
   - 小地图使用安全区坐标，HUD/排行榜最多每 100ms 更新且内容不变时不重写 DOM。

3. **模拟与 AI**
   - 将移动、吐出物和粒子阻尼改为 `dt` 计算。
   - 为 AI 增加 80% 移动速度、75% 分身冲量和 120ms 决策间隔，保留性格差异。
   - 增加临时均匀网格空间索引，供彩豆附近查询和碰撞候选使用。

4. **渐进合球**
   - 冷却仍为 4.5 秒；冷却结束后按质量中心施加限速聚合力。
   - 只有满足原有重叠条件才合并，保持最多 16 个玩家分身。

5. **验证与发布**
   - 增加 Node 回归测试并运行 `npm.cmd test`、JavaScript 语法检查。
   - 在 852x393 DPR3、852x320 和 1280x720 尺寸检查控件、小地图、画布和停止移动行为。
   - 提交到 `main` 并推送 GitHub Pages。

## 验收重点

- iPhone 横屏底部操作区不被浏览器工具栏遮挡。
- 轮盘按住不动时持续保持方向，松手后球停止。
- 手机内部画布不超过 DPR2 对应像素量，背景视觉仍在。
- AI 不再比玩家快，目标不会每帧剧烈抖动。
- 分身冷却结束后会逐渐靠拢并在重叠时正常合并。
